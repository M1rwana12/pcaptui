<h3 align="center">Аналіз від Wireshark — там, де вже лежить захоплений трафік.</h3>

<p align="center">
  <code>pcaptui</code> — це термінальний інтерфейс до <code>tshark</code>: список пакетів,
  дерево протоколів і шістнадцяткова панель, через SSH, на машині без графіки — не
  перетягуючи захоплення на свій комп'ютер.
</p>

<p align="center">
  <img src=".github/assets/demo.svg" alt="Відкрити захоплення, спитати що в ньому, спитати що з ним не так, і опинитись на проблемних пакетах" width="100%">
</p>

**Що показує запис вище**, на захопленні telnet із 92 пакетів:

- <kbd>y</kbd> — **що є в цьому файлі.** Ієрархія протоколів деревом і частка пакетів,
  яку займає кожен протокол.
- <kbd>esc</kbd> <kbd>e</kbd> — **що з ним не так.** Expert Information: те, що
  позначили дисектори самого Wireshark, найгірше вгорі. Тут — спотворений пакет.
- <kbd>enter</kbd> — **пакети, про які йдеться.** Рядок стає фільтром відображення, і
  список пакетів звужується саме до них. Так працює кожна таблиця тут.

## Встановлення

```bash
go install github.com/m1rwana12/pcaptui/cmd/pcaptui@latest
```

Або візьміть бінарник з [останнього релізу](https://github.com/m1rwana12/pcaptui/releases/latest)
— 13 пар платформа/архітектура, з контрольними сумами. У дистрибутивах пакета ще нема;
рецепти написані й чекають у [`packaging/`](packaging/).

```bash
pcaptui -r traffic.pcap                # файл
pcaptui -r traffic.pcap 'tcp.port==80' # файл із фільтром
pcaptui -i eth0 'port 443'             # інтерфейс і фільтр захоплення
tcpdump -w - port 53 | pcaptui -r -    # конвеєр (Unix; на Windows не працює)
```

**Потрібен [`tshark`](https://www.wireshark.org) у `PATH`** — саме звідти беруться всі
дисектори, фільтри й статистики. Мінімум 1.10.2 перевіряється на старті, а якщо
`tshark` не знайдено, `pcaptui` прямо це каже й не запускається — замість того щоб
зламатись згодом так, ніби це зіпсоване захоплення. Двом виглядам потрібне свіжіше:
Credentials — від tshark 3.2, а збирання потоку TLS найкраще працює від 4.4.

## Що ви отримуєте

**Захоплення, у якому можна рухатися.** Список пакетів, який гортається, дерево
протоколів, яке розгортається, і шістнадцяткова панель, що підсвічує байти того поля,
яке ви вибрали. `tcpdump` друкує рядки; тут можна дивитися.

**Фільтри відображення Wireshark, перевірені до того, як щось коштувати.** Той самий
синтаксис, і коробка фільтра червона, поки вираз хибний. Фільтр із командного рядка теж
перевіряється — в обох формах, `-Y` і позиційній, — тож описка спиняє програму з
поясненням від самого `tshark`, а не відкриває три порожні панелі.

**Дисектори Wireshark, усі.** `pcaptui` не розбирає протоколи сам: у цьому репозиторії
немає ні розбору протоколів, ні власних уявлень про них. Він питає `tshark` і малює
відповідь. Wireshark вивчив новий протокол — значить, і цей уміє.

**Відповіді, а не лише пакети.** Захоплення відповідає на чотири питання — що це за
файл, що з ним не так, що в ньому є і хто на дроті — і Overview питає всі чотири
одразу, одним проходом. Він відкривається сам, коли файл дочитано, бо екран із першим
пакетом не відповідає ні на одне з них.

**Він каже, коли показує не все.** Колонка, завузька для свого значення, закінчується
`…`, а не тихо показує коротшу адресу; заголовок каже, скільки пакетів і чи список
короткий через фільтр; статистика, яка нічого не знайшла, каже це словами, а не
відкриває порожню коробку; а захоплення, завелике щоб підсумувати його безкоштовно,
підсумок **пропонує**, а не робить — див. [межі](#чого-він-не-робить).

## Аналіз

Одинадцять виглядів, по клавіші на кожен — та сама клавіша стоїть біля пункту в меню
Analysis. Кожен рядок кожної таблиці можна натиснути: він стає фільтром відображення.

| Клавіша | | |
|---|---|---|
| <kbd>o</kbd> | **Overview** | усі чотири питання одразу, зі спарклайном, коли саме йшов трафік |
| <kbd>e</kbd> | Expert Information | що дисектори вважають неправильним |
| <kbd>y</kbd> | Protocol Hierarchy | що є в цьому захопленні, деревом |
| <kbd>t</kbd> | Endpoints | хто на дроті, найактивніші вгорі, IPv4 та IPv6 |
| <kbd>a</kbd> | Credentials | логіни, які це захоплення несе відкритим текстом |
| <kbd>w</kbd> | HTTP | чим закінчились відповіді HTTP, за статусами |
| <kbd>d</kbd> | DNS | що питали і з якими кодами відповіли |
| <kbd>v</kbd> | Conversations | хто з ким говорив, у пакетах і байтах |
| <kbd>s</kbd> | Reassemble stream | потік, до якого належить пакет; `:streams tcp`\|`udp`\|`tls`\|`websocket`\|`http2` — вибрати родину |
| <kbd>p</kbd> | Capture file properties | розмір, тривалість, інкапсуляція, хеші |
| <kbd>x</kbd> | Export objects | записати на диск файли, які несло це захоплення |

</p>

Статистики враховують чинний фільтр відображення, тож їх можна питати про підмножину, і
кожна називає фільтр у себе в заголовку. Два винятки, обидва свідомі й обидва видимі:

- **Credentials фільтр ігнорує** і каже про це у власному заголовку. `tshark` приймає
  фільтр для цього крану, виходить успішно й однаково повідомляє ті самі логіни —
  заміряно фільтром, який виключає кожен пакет у файлі, — тож твердити, ніби фільтр
  подіяв, було б гірше, ніж визнати, що ні.
- **У Conversations для цього є галочка**, типово знята: цей вигляд зазвичай відкривають
  саме щоб побачити, хто там узагалі є, а не хто лишився після фільтра.

### Збирання потоку

<kbd>s</kbd> збирає транспортний потік — TCP, або UDP, якщо пакет не TCP. Ще три родини
питають на імʼя, бо кожна з них може законно повернутися порожньою, і це не має бути
несподіванкою:

| | |
|---|---|
| `:streams websocket` | самі повідомлення, розмасковані, без рукостискання HTTP і без байтів обрамлення |
| `:streams http2` | одна розмова з мультиплексованого з'єднання, заголовки розкодовані в текст |
| `:streams tls` | розшифрований вміст, для якого потрібні ключі — див. нижче |

## Розшифрування TLS

З ключами сесії вміст TLS стає звичайними шарами протоколів, і `:streams tls` показує
відкритий текст:

```bash
export SSLKEYLOGFILE=~/keys.log     # далі запустіть браузер або curl
pcaptui --tls-keylog ~/keys.log -r traffic.pcap
```

`pcaptui` перевіряє файл ключів до старту й відмовляється запускатись, якщо його немає
або його не вдається прочитати. `tshark` приймає шлях до неіснуючого файлу ключів,
стартує нормально, виходить із нулем і нічого не розшифровує — тож інакше описка в
шляху виглядала б точнісінько як трафік, ключів до якого у вас ніколи не було.

## Як рухатись

| | |
|---|---|
| <kbd>/</kbd> | фільтр відображення |
| <kbd>tab</kbd> | перемикання панелей |
| <kbd>&#124;</kbd> <kbd>\\</kbd> | розкладка панелей, збільшення панелі |
| <kbd>ctrl</kbd>+<kbd>f</kbd> | пошук — фільтром, шістнадцятковим, текстом або регуляркою |
| <kbd>m</kbd><kbd>a</kbd> <kbd>'</kbd><kbd>a</kbd> | позначити пакет, повернутися до нього |
| <kbd>c</kbd> | режим копіювання — пакети, поля або цілий потік |
| <kbd>?</kbd> | усе інше |

Клавіші vim працюють усюди. Мишка — у більшості терміналів.

## Чи це для вас?

**Так, якщо** захоплення лежить на сервері, або завелике щоб його переносити, або ви
вже знаєте фільтри Wireshark і хочете їх там, де трафік.

**Ні, якщо** ви на десктопі, де встановлений Wireshark, і файл перед вами. Графічний
Wireshark кращий за будь-який термінал, і це існує для випадків, коли його немає. Якщо
потрібна одна відповідь у скрипті, а не сеанс — беріть сам
[`tshark`](https://www.wireshark.org); а якщо хочеться тієї самої ідеї від її автора —
[termshark](https://github.com/gcla/termshark), на кодовій базі якого це побудовано.

### Чого він не робить

- **Не читає конвеєр на Windows.** `pcaptui -r -` працює на Unix; збірка для Windows
  прямо це каже й не запускається.
- **Вище 10 МБ Overview статистику пропонує, а не запускає.** Це один прохід по всіх
  пакетах, і він тим повільніший, чим більший файл — заміряно: 85 МБ це 19 с на Linux і
  47 с на macOS. Само собою відкривається те, що файл каже про себе, і це коштує частку
  секунди на будь-якому розмірі. <kbd>o</kbd> запускає решту, коли ви попросите.
  `:set start-view packets` вимикає це зовсім.
- **Збирання потоку TLS потребує файлу ключів** — і прямо це каже, а не показує порожню
  панель: без ключів немає нічого розшифрованого, що можна було б збирати.
- **Не збирає потоки QUIC.** Вони захищені після рукостискання, тож без ключів відповідь
  була б порожня — а перевірити це тут по-справжньому нічим. Записано, а не зроблено
  наполовину.
- **Не захоплює живий трафік на Windows без [Npcap](https://npcap.com)** — це вимога
  `tshark`, не цієї програми.
