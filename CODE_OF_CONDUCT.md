# Code of Conduct

## The short version

Be decent. Assume the person on the other side is trying to help, including
when they are wrong.

## What that means here

**Talk about the code, not the person.** "This breaks on Windows because the
test asks for `TMPDIR`" is useful. "Did you even test this?" is not, and it is
the same information with the useful part removed.

**Say what you measured.** Disagreements about behaviour end quickly when
somebody runs the thing. Disagreements about opinions do not end at all.

**A question is not an imposition.** Somebody asking how to read a capture over
SSH is the reason this exists. If a question keeps coming up, that is a
documentation bug, not a user problem.

**Nobody is owed your time, and you are not owed theirs.** Maintainers can say
no. Contributors can walk away. Neither needs a justification.

## Not welcome

Harassment, insults, or personal attacks. Sexual attention or imagery.
Publishing someone's private information. Sustained disruption of a discussion.
Any of the above dressed up as a joke.

This applies in issues, pull requests, commit messages and code review — every
place this project happens.

## Enforcement

Report to the maintainer through GitHub, or privately through [security
advisories](https://github.com/m1rwana12/pcaptui/security/advisories/new) if it
needs to stay confidential.

Reports are read. What happens next depends on what happened: a word in
private, a comment removed, or being blocked from the repository. Serious or
repeated behaviour goes straight to the last one.

If a report is about the maintainer, say so in it. That is worth reporting too,
and there is no separate process to hide behind here.
